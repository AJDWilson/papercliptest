# Working with the CEO

This guide explains how to interact with Joseph Whelan, the CEO agent.

## What the CEO Does

The CEO operates at the strategic and coordination level:

✅ **Does:**
- Triages incoming work
- Routes tasks to appropriate owners
- Hires department heads as needed
- Unblocks teams
- Makes product/priority decisions
- Communicates with stakeholders
- Coordinates cross-functional work

❌ **Does NOT:**
- Write application code
- Fix bugs directly
- Implement features
- Run builds or tests
- Create designs

## How to Assign Work

### Option 1: Create a Task
Assign a task to the CEO with clear requirements:
```
Title: Add user authentication
Description: We need to add user login with email/password
```

The CEO will:
1. Understand the requirement
2. Determine this is technical work
3. Hire a CTO if one doesn't exist
4. Delegate to the CTO via subtask
5. Follow up on progress

### Option 2: Ask a Question
The CEO can answer strategic questions:
- "What's our current team structure?"
- "What work is in progress?"
- "Should we prioritize feature X or Y?"

### Option 3: Request a Decision
Ask the CEO to make a call on:
- Priorities and roadmap
- Resource allocation
- Hiring needs
- Cross-team conflicts

## Response Format

The CEO will typically respond by:

1. **Acknowledging** the request
2. **Analyzing** what's needed
3. **Delegating** to the right owner (with subtask ID)
4. **Documenting** the delegation
5. **Confirming** next steps

## Delegation Chain

```
Board/User
    ↓
  CEO (triages & routes)
    ↓
Department Head (executes or delegates further)
    ↓
Individual Contributors (if applicable)
```

## Status Checks

To check on work:
- Ask the CEO directly: "What's the status of task X?"
- The CEO will check with the assigned owner
- The CEO will report back with current state and any blockers

## Escalations

If work is blocked:
- The assigned owner escalates to the CEO
- The CEO determines how to unblock (resources, decisions, etc.)
- The CEO takes action or escalates further to the board

## Memory

The CEO maintains organizational memory:
- Facts about the company and products
- Decision rationale
- Team structure and relationships
- Past work and outcomes

This memory persists across conversations, so you don't need to re-explain context.

## Best Practices

1. **Be clear about what you want**: "Add feature X" not "Can you work on the app?"
2. **Provide context**: Share relevant background and constraints
3. **Set expectations**: Include deadlines or priority if relevant
4. **Trust the process**: The CEO will route work appropriately
5. **Follow up if needed**: Ask for updates if work seems stalled

## Example Interactions

**Good:**
> "Implement a shopping cart feature with add/remove items, quantity adjustment, and checkout button. This is a high priority for next sprint."

CEO response: Delegates to CTO, creates subtask, provides acceptance criteria.

**Also Good:**
> "Should we focus on mobile responsiveness or dark mode first?"

CEO response: Makes decision based on strategy, explains rationale.

**Less Good:**
> "Do something with the app"

Issue: Too vague. CEO will ask for clarification.

---

The CEO is here to lead, coordinate, and enable. Bring work and questions, and they'll ensure the right people handle it.
